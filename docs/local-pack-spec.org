* Goal
Transit-style: compile GTFS once, ship a Montréal pack, answer map nearby
and stop departures *on the phone*. Worker becomes publisher (manifest +
optional RT overlay), not a SQL warehouse.

App north star unchanged: open the map, see nearby stops, know what comes
next. Same JSON shapes as today (~NearbyStop~, ~Departure~ in
~src/lib/types.ts~).

* Why
Prod D1 (~mewtransit~, id ~b9fffb8a-200e-4fe0-842f-c4b3a615d7e6~):

- 4.1M STM ~stop_times~ → 12.95M rows written vs free 100k/day
- 466 MB vs 500 MB free cap
- Nearby join (~departuresForStations~ in ~mewtransit-api/src/lib/store.ts~)
  scanned tens of millions of rows, p99 > 1s

That query filters ~platform.station_id IN (…)~ and ~t.service_id IN (…)~
with *no* ~departure_sec~ bound and *no* ~LIMIT~. STM weekday service ids
are almost the whole agency. Indexes we built (~stop_times_stop_sec~) are
not on those predicates.

GTFS-RT does not replace the timetable. STM public trip-updates is iBus
(bus). Metro is not in it.

* Pack format

** One SQLite file
~montreal-<YYYYMMDD>.db~ (UTF-8, SQLite 3). Built on the laptop/CI with
~better-sqlite3~. Opened on device with ~expo-sqlite~.

Do *not* use D1 to build it. Do *not* emit a giant .sql for ~wrangler d1 execute~.

** Coverage
One file for STM + REM + exo trains.

Materialize departures for:

- ~civilDate~ (America/Toronto)
- ~civilDate + 1 day~
- leftover after-midnight trips from ~civilDate − 1~ (~departure_sec >= 86400~)

Same semantics as ~departuresForStations~ today. A pack built at 03:00
lasts until the next night without a hole at midnight.

** Schema (exact)

#+begin_src sql
PRAGMA journal_mode = OFF;
PRAGMA synchronous = OFF;   -- builder only
PRAGMA foreign_keys = OFF;

CREATE TABLE meta (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

CREATE TABLE routes (
  id TEXT PRIMARY KEY,
  agency_id TEXT NOT NULL,
  short_name TEXT NOT NULL,
  long_name TEXT NOT NULL,
  color TEXT NOT NULL,
  text_color TEXT NOT NULL,
  mode TEXT NOT NULL
);

CREATE TABLE stops (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  lat REAL NOT NULL,
  lon REAL NOT NULL,
  agency_id TEXT NOT NULL,
  wheelchair INTEGER NOT NULL DEFAULT 0,
  is_station INTEGER NOT NULL DEFAULT 0,
  station_id TEXT NOT NULL
);

CREATE TABLE stop_routes (
  stop_id TEXT NOT NULL,
  route_id TEXT NOT NULL,
  PRIMARY KEY (stop_id, route_id)
);

-- One row = one scheduled departure at a *station* (parent).
-- station_id is denormalized so nearby does not join platforms.
CREATE TABLE departures (
  station_id TEXT NOT NULL,
  stop_id TEXT NOT NULL,
  trip_id TEXT NOT NULL,
  route_id TEXT NOT NULL,
  service_ymd INTEGER NOT NULL,
  departure_sec INTEGER NOT NULL,
  headsign TEXT NOT NULL
);

CREATE INDEX stops_station_lat_lon ON stops (is_station, lat, lon);
CREATE INDEX stop_routes_stop ON stop_routes (stop_id);
CREATE INDEX dep_station_sec ON departures (station_id, service_ymd, departure_sec);
#+end_src

~meta~ keys (all strings):

- ~schema_version~ = ~1~
- ~pack_id~ = ~montreal~
- ~civil_date~ = ~YYYY-MM-DD~ (the pack's "today")
- ~timezone~ = ~America/Toronto~
- ~built_at~ = ISO-8601 UTC
- ~stm_feed_version~, ~rem_feed_version~, ~exo_feed_version~ (empty if missing)

~stops~: only ~is_station = 1~ rows need to appear in nearby, but *keep
platforms* if they help debugging; nearby *must* filter ~is_station = 1~.
~station_id~ on a parent is its own ~id~. Names already passed through
~displayStopName~ / agency normalizers.

~departures.station_id~ = parent station id (~platform.station_id~ today).
~departures.stop_id~ = platform id (needed later for RT match).

Do not store calendar, trips, or raw ~stop_times~ in the pack. The builder
resolves services and throws the warehouse away.

** Algorithm
1. For each agency, download zip to ~tmp/gtfs/<agency>.zip~ (reuse if
   present and ~If-None-Match~ / mtime is fine). Record ETag.
2. Unzip to ~tmp/gtfs/<agency>/~.
3. Catalog: reuse ~normalizeFeed~ for rem/exo. For STM, reuse ingest's
   streaming path for ~stop_times.txt~; still run ~normalizeStmStops~ on
   ~stops.txt~.
4. Compute service id sets for ~yesterday~, ~today~, ~tomorrow~ with the
   same calendar rules as ~servicesOn~ / ~rawServiceIdsValidFrom~
   (calendar + calendar_dates). Prefix service ids.
5. Walk ~stop_times~ (stream STM). Keep a row if its trip's service is in
   those three sets. Map stop → ~station_id~. Skip rows whose stop is
   unknown.
6. Insert into a *new* sqlite file (never mutate a previous pack in
   place). Batch inserts (thousands per transaction).
7. Write ~meta~, then ~manifest.json~ next to the db. Print:

   : agencies, station_count, departure_count, bytes, path

confirming the service filter is actually applied. Never "fix" size by

** Sync policy
- On app foreground / first launch: fetch manifest (2 s timeout). If
  newer (different ~sqliteSha256~ or ~civilDate~), download in
  background. Map must render with the *previous* pack immediately.
- If no local pack yet: show existing loading/error UI, do not hang the
  map on a 40 MB download without a progress string.
- If download fails: keep old pack; set a soft banner later (not in v1
  if polish is separate).
- Source of ~current.json~ v1: ~EXPO_PUBLIC_PACK_MANIFEST_URL~ (R2 public
  or Worker). Default can be a workers.dev or R2.dev URL once uploaded.
  Do *not* hardcode a personal machine path.

** Local nearby (must match today's product)
Inputs: ~lat, lon, radiusM=1500, limit=16, departures=3~.

1. Bbox pad +250 m (same as ~stationCandidates~).
2. ~SELECT~ stations ~is_station = 1~ in bbox.
3. Haversine, drop > ~radiusM~, sort by distance.
4. Attach ~routeIds~ from ~stop_routes~ for the *picked* ids only.
5. ~pickNearby~ so rem/exo/~stm:STATION_*~ are not buried by buses.
6. For each picked station, next ~departures~ rows (query below).
7. Map ~departureTime~ with ~gtfsDepartureUtc(service_ymd, departure_sec)~.
   *Port* ~time.ts~ into the app (~src/lib/time.ts~) — do not reimplement
   DST. ~minutes~ via the same ~minutesUntil~. ~realtime: false~ for now.

Departure SQL:

#+begin_src sql
SELECT d.stop_id, d.trip_id, d.route_id, d.service_ymd, d.departure_sec,
       d.headsign, r.short_name, r.long_name, r.color, r.text_color,
       r.agency_id, r.mode
FROM departures d
JOIN routes r ON r.id = d.route_id
WHERE d.station_id = ?
  AND (
    (d.service_ymd = ? AND d.departure_sec >= ?)
    OR (d.service_ymd = ? AND d.departure_sec >= ?)
  )
ORDER BY d.service_ymd, d.departure_sec
LIMIT ?
#+end_src

Binds: ~stationId, todayYmd, todayDaySec, yesterdayYmd, 86400+todayDaySec, limit~.

~Departure.id~ = ~${tripId}:${stationId}:${departure_sec}~ (same as store.ts).

Stop detail (~src/app/stop/[id].tsx~): same query, ~limit=24~. 404 if
stop missing.
