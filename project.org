Agencies in scope: *STM* (metro + bus), *REM*, *Exo* (trains first, buses later).

- this one — Expo app
- [[file:../mewtransit-api/readme.org][mewtransit-api]] — Cloudflare Worker that owns GTFS and serves the app

SQLite → query on device). STM is too big for D1 *and* too big to
bundle as a dump.

~transit-worker~ experiment (raw STM dump into D1) is retired.

** Data notes
STM static: ~https://www.stm.info/sites/default/files/gtfs/gtfs_stm.zip~
(page says current file valid until 2026-10-25).
Exo trains: ~https://exo.quebec/xdata/trains/google_transit.zip~
Exo also publishes a pile of bus-sector zips — later.
REM: ~https://gtfs.gpmmom.ca/gtfs/gtfs.zip~

STM ~stop_times~ is huge (~5M in the zip, 4.1M remaining-service). It is
a *publishing* format. Compile it into per-station departures in a city
pack. Never load it into D1. Never ship the 1.4GB dump in the app binary.

4.1M rows are unique trip×stop events, reused across many calendar days.
A weekday pack (today+tomorrow services only) should be tens of MB, not
466 MB.

Live data is a first-class goal. Static pack is the timetable; GTFS-RT
trip updates paint minutes when online. Metro RT is generally not public.
